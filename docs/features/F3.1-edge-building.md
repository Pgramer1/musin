## 1. Purpose

P2 left the data as facts per recording: who is billed (main or featured), who produced or performed, and when each recording first came out. The research questions need an **artist–artist graph**. F3.1 turns those per-recording facts into the four typed, weighted edge types of PRD §8.2. It also applies every graph-level filter the earlier phases deferred: oversized credits (FR-10), group ↔ own member (FR-11), `Character` artists (D-021), classical (OD1), and `min_recordings` (OD2). It writes the four §8.1 tables that F3.4 exports to Neo4j and that Spark-side analyses (RQ3) read directly.

## 3. How it works

```
clean/credits ──size ≤ max_credit_size──▶ credit_edges ─────────┐
clean/contributions ──same recordings──▶ contribution_edges ─────┤  edge instances
                                                                 ▼  (recording, src, dst, type)
excluded artists (type / classical) + band-member pairs ──▶ mark_drops ──▶ kept instances
                                                                 │  + clean/recording_years
                                       ┌─────────────────────────┴─────────────────┐
                                aggregate_edges                          aggregate_by_decade
                                       │  node rule (§8.3)                          │
                                       ▼                                            ▼
                                graph/edges ──endpoints──▶ graph/nodes_artist, graph/artist_genre
                                                             graph/edges_by_decade (only kept edges)
```

1. **Credit size and FR-10.** Size = rows of the recording in `clean/credits` (special artists already removed, one row per artist). Recordings above `max_credit_size` are dropped **before** pairing, because the self-join is quadratic, and they produce no edges of any type ([D-026](../decisions.md#d-026--graph-build-rules-credit-size-filter-scope-and-drop-order) §1–2). `Character` artists still count towards the size, so the D-021 sensitivity build differs from the main build only by Character edges.
2. **Credit edges (PRD §8.2).** A self-join of each recording's credits:
   - main × main and featured × featured → `CO_CREDITED`, stored once with `src_id < dst_id`
   - main → featured → `FEATURED`
   - featured → main gives nothing (the edge already exists in the other direction).

   *Example:* "A feat. B & C" gives A→B FEATURED, A→C FEATURED, B–C CO_CREDITED. A recording whose only main artist was removed (D-020) gives no FEATURED edge.
3. **Contribution edges.** Every `clean/contributions` row (one per recording, artist, edge type; D-022) pairs with every **main** artist of the recording. Featured guests are not targets (§8.2).
4. **Drops, labelled not filtered.** `mark_drops` adds a `drop_reason` to every instance:
   - self-loop: a producer or performer who is also the main artist
   - excluded artist type (`Character`, D-021): either end
   - excluded classical (only if OD1 is false; D-026 §4)
   - band member: the unordered pair is in "member of band", for every edge type (D-026 §3)

   One `groupBy(edge_type, drop_reason)` then gives every filter's effect from a single cached frame. The kept set does not depend on the label order.

   *Rejected:* removing excluded artists from the credits before pairing. It gives the same edges (roles are already fixed by F2.2), but the per-filter counts that D-021 asked F3.1 to report would be lost.
5. **Aggregation.** Kept instances are de-duplicated, joined with `clean/recording_years`, and grouped per (src, dst, type):
   - `weight` = distinct recordings
   - `first_year` / `last_year` = min / max known first-release year (null if none is known)

   `edges_by_decade` groups the same instances by `floor(year / 10) * 10`, leaving out unknown years (D-011). Both tables come from one frame, so the §8.1 invariant (decade weights ≤ edge weight) holds by construction; F3.3 checks it formally.
6. **Node rule (PRD §8.3).** An edge is kept if both endpoints have `recording_count ≥ min_recordings`. Graph artists are exactly the endpoints of kept edges, so one pass gives "meets the threshold **and** has an edge". `recording_count` counts recordings where the artist is billed **or** holds a contribution credit ([D-027](../decisions.md#d-027--recording_count-counts-billed-and-contribution-credits)). Otherwise pure producers and session musicians would be removed at any threshold, together with all their contribution edges.
7. **Node tables.** `nodes_artist` joins the graph artists with `clean/artists`, the recording counts, and `clean/artist_primary_genre`. `artist_genre` is `clean/artist_genres` limited to graph artists, with only the §8.1 columns.

**Sample mode** reads `credits`, `contributions`, and `recording_years` from `$MUSIN_DATA/sample/f<f>/clean/` and writes to `sample/f<f>/graph/` (D-019). Artist-level inputs (artists, genres, band membership) always come from the full layers. Building and validating the dev sample graph that member B uses is F3.2.

*Rejected alternatives:*
- **Applying FR-10 to credit edges only.** A 40-artist cast recording with 20 performer credits would still produce 800 contribution edges.
- **Counting credit size after removing Characters.** This would let the D-021 switch change which recordings count as "large".
- **Iterating the node rule until nothing changes.** `min_recordings` does not depend on edges, so one pass is exact.

## 8. Known issues and limitations

- **Billed contributors count twice in COLLAB.** Before the type and band filters, 4,026,709 of 10,339,747 non-self `PERFORMED_FOR` instances (38.9 %) and 138,726 of 2,762,816 `PRODUCED_FOR` (5.0 %) come from a contributor who is *also billed* on the same recording. Example: Springsteen sings on "Bruce Springsteen & The E Street Band" recordings, giving both `CO_CREDITED` and `PERFORMED_FOR`. This follows PRD §8.2. However, D-017 sums all types per pair, so such recordings weigh double in COLLAB. Changing it means changing §8.2, so it is a G1 / contract question, not an F3.1 fix.
- **Backing bands aren't caught by FR-11.** The E Street Band members are members of The E Street Band, not of "Bruce Springsteen", so their `PERFORMED_FOR` edges to him stay. Only direct "member of band" pairs are removed; "is person" / alias relationships (one person under two names) are not handled either.
- **Spoken word** (audiobook authors and narrators) forms some of the heaviest edges. F1.4 flagged this, and no feature ID covers a filter yet.
- **Classical dominates hub rankings** while OD1 is `include_classical: true`.
- **Coverage biases carry over from P2:** contribution credits cover about 10 % of recordings, and genres label 23.4 % of nodes.
- **Stage checks only.** The formal graph-layer suite (decade invariant, comparison with the previous run's counts) is F3.3.
- **`edges` and `nodes_artist` are written as 200 Parquet files each** (Spark's default shuffle partitions). This is harmless for Spark; F3.4 writes its own CSVs.
