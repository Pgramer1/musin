## 1. Purpose

P3–P5 wrote their results to `reports/tables/` and some figures to `reports/figures/`. The report needs more than that:

- **Missing figures:** RQ2 (communities), RQ4 (centrality agreement), the validation, and the PageRank engine comparison (F5.2/F5.3) had tables but no figure.
- **A comparison that existed only in prose:** the F4.7 doc compared the main graph with its `characters` and `classical` variants using numbers computed by hand. RULES §9 says report numbers come from `reports/tables/`.
- **Raw CSVs aren't report tables:** they carry full float precision, provenance columns and every row.
- **No way to check FR-24:** nothing listed which figure or table comes from which stage.

F6.1 adds one stage that fills these gaps from the existing tables, so the report (F6.3) and slides (F6.4) can quote generated files only.

## 3. How it works

```
reports/tables/*.csv  ──check_one_build('full')──┐
reports/tables/variants/<v>/*.csv ──check_one_build('full-<v>')──┤
                                                  ▼
             derived: sensitivity_top_lists / sensitivity_agreement (per variant in config `variants`)
                      graph_instances, pipeline_funnel        ──▶ reports/tables/*.csv
                                                  │
              figures (7)  ──▶ reports/figures/*.png
              tables (20)  ──▶ reports/tables/report/<name>.{md,tex}   (folder rewritten)
              manifest     ──▶ reports/README.md
```

1. **Read only the reports layer.** Every input is an aggregated table that a P1–P5 stage already wrote and that is committed. The stage never recomputes a metric; it selects, joins, rounds and draws. That keeps it cheap (no Spark session, no Neo4j connection), so it can run beside any heavy job and after every re-run.
   *Rejected:* drawing the figures inside each P4/P5 stage. That would mean re-running hour-long stages (F4.1 takes about 2.7 h) to change a label, and it can't produce cross-graph comparisons, which need several stages' outputs.
2. **One-build guard** (D-044 §2). Every P4/P5 table stamps `graph` and `edges_fingerprint` on each row. Before writing anything, the stage checks that:
   - all stamped tables in `reports/tables/` name `full` and one fingerprint (`-2227712706449027820962`);
   - each variant folder names `full-<variant>` and its own fingerprint.

   F4.4's trends table carries the graph name only and is checked for that. Unstamped tables (profiling, `graph_build_summary.csv`) describe the build itself. A leftover table from an older import (see the betweenness finding, P4 §7) would stop the stage instead of quietly entering the report.
3. **Sensitivity comparison** (D-044 §3). For each variant in config `variants` and each centrality list (2 projections × 3 measures), plus the bridge list:
   - the top-k artist sets by MBID (k = `analysis.top_k_centrality` 20, `analysis.top_k_bridges` 25);
   - Jaccard, common artists and entrants, i.e. the variant's artists that are not in the main list;
   - **admitted entrants:** entrants of the kind the variant lets in. The kind is derived from the config difference, not hard-coded: `characters` drops `Character` from `exclude_artist_types`, so admitted means `type == Character`; `classical` turns `include_classical` on, so admitted means primary genre `classical`.

   *Example:* COLLAB PageRank, `characters`: 16 of 20 artists in common (Jaccard 0.667); 4 entrants, all Characters (初音ミク #1, 鏡音リン #11, 重音テト #14, GUMI #16).

   The stage refuses to compare if a top list is shorter than k, so a shortened list can't quietly lower a Jaccard.
4. **Graph build accounting.** `graph_instances.csv` reshapes F3.1's `instances_<TYPE>_<fate>` counters into one row per (edge type, fate). `pipeline_funnel.csv` lists 17 steps from dump rows to Neo4j pairs; each row names the table and metric it was copied from. Metric names that embed the credit-size cap (`recordings_over_10_artists`) are found by prefix, so a different `max_credit_size` doesn't break the stage.
5. **Figures.** All use the reference palette:
   - categorical slots in fixed order;
   - at most three colours where marks sit side by side, with a different marker shape per series;
   - a legend on every multi-series chart and direct value labels where they fit;
   - text in text colours, never in series colours.

   The community genre mix can't give 15 genres a colour each. Each bar instead shows its own largest genre (blue) and second genre (orange), named inside the bar, and the rest in grey. A second genre too narrow to name is listed in the right-hand column.
6. **Report tables.** `ReportTable` holds formatted strings, so the Markdown and LaTeX versions show identical numbers. Each file starts with a comment naming its source CSVs and the command. Notes carry the caveats the numbers need: betweenness ranks rather than exact order (P4 §7), spoken word still included (D-040), the pre-registration (D-037).
   *Rejected:* `pandas.to_markdown`/`to_latex`. They need extra packages in the image (tabulate, jinja2) and give less control over escaping and captions.
7. **Manifest.** A catalogue of glob patterns (first match wins) maps each file under `reports/` to a report section, the feature that writes it and that feature's command. A file with no entry is listed under "Not catalogued" and logged as a warning; this run had none.

## 5. Configuration

No new keys (D-044 §7).

| Key (`config/pipeline.yaml`) | Value used | Meaning |
|---|---|---|
| `reports_dir` | `reports` | Where the stage reads and writes |
| `analysis.top_k_centrality` | 20 | k of the centrality top-list comparison |
| `analysis.top_k_bridges` | 25 | k of the bridge-list comparison |
| `variants` | `characters`, `classical` | Graphs compared with the main graph; each variant's `filters` define its admitted kind |
| `filters.exclude_artist_types`, `filters.include_classical` | `[Character]`, `false` (main) | Compared with each variant's values for the admitted-entrant rule |

## 6. How to run

```bash
docker compose exec spark python -m musin.report --config config/pipeline.yaml
```

There is no sample mode. The stage describes the committed report of the full graph, and sample runs never write to `reports/` (D-019). Run it after any P4/P5 stage that rewrites a report table. Runtime on the reference machine: 2.2–2.3 s.

## 7. Verification and results

Run 2026-10-20 on the post-G1 tables. Main graph `full`, edges fingerprint `-2227712706449027820962`; variants `full-characters` (`-1131787253908781684974`) and `full-classical` (`-3716276720548320596788`). The guard passed for all three folders.

- **Generated sensitivity numbers match F4.7's hand-computed ones:**
  - `characters`, top-20 Jaccard: COLLAB weighted degree 0.905, PageRank 0.667, betweenness 0.600; credit-only 0.905, 0.538, 0.600. Bridge top 25: 0.852.
  - `classical`, top-20 Jaccard: 0.250–0.481 across the six lists; bridge top 25: 0.613. No classical artist enters the bridge list.
  - Agreement (`sensitivity_agreement.csv`): for `characters`, every |Δρ| ≤ 0.004 and every |ΔJaccard| ≤ 0.034, as F4.7 states.
  - Admitted entrants: in `characters`, only the voicebanks the F4.7 doc names. In `classical`, 7–12 classical entrants per list, mostly orchestras, plus Hans Zimmer and Jerry Goldsmith (PageRank), whose primary genre is classical in the data.
- **Funnel spot checks against the source tables:**
  - kept edge instances sum to 12,329,531, equal to the COLLAB weight in `gds_projections.csv`;
  - edges 3,078,519 and nodes 1,135,461, as in `graph_build_summary.csv`.
- **Determinism:** two consecutive runs produced byte-identical outputs (52 files, MD5).
- **Figures:** all seven were rendered and checked by eye for overlapping labels, clipping and legend placement. Three rounds of layout fixes:
  - legend positions;
  - size-bucket labels;
  - a segment label that overflowed its bar.
- **Manifest:** 85 files under `reports/` plus 20 report tables catalogued; 0 not catalogued.
- **Tests:** `pytest` 266 passed (248 before F6.1, 18 new); `ruff check` and `ruff format --check` clean.

## 8. Known issues and limitations

- **Team choices (settled by member A, 2026-10-20):**
  - **Ego figures stay as generated:** the three F4.3 ego figures show the top three bridges, and #1 is Putumayo, a record label credited as an artist (P4 §7). The report explains it as a data artefact. The rejected alternative was a config key listing the artists to draw (a contract change, PRD §8.4) plus an F4.3 re-run.
  - **Separation pairs stay as the F4.5 examples:** Frank Sinatra → Snoop Dogg, Johnny Cash → Armin van Buuren, Manfred Eicher → Gucci Mane (`separation_paths`).
- **Still open:** the F4.6 spot-check verdicts need both members' review before the top lists are quoted.
- **Inherited caveats travel with the numbers** in the table notes, not fixed here: sampled betweenness across imports (P4 §7), spoken word in the graph (D-040), genre coverage.
- **The LaTeX tables need XeLaTeX or LuaLaTeX** (CJK artist names, ρ, ×, Δ) plus booktabs. Long tables (`rq1_bridges_top`, `sensitivity_top_lists`) are wider than a portrait page; the report may need `\resizebox`, landscape, or fewer columns. That is a layout choice for F6.3.
- **The manifest catalogue is hand-maintained:** a new report file needs an entry in `musin.report.manifest.CATALOGUE`, or it is flagged as not catalogued.
- **No architecture diagram:** it shows no data, so FR-24 doesn't cover it. F6.3/F6.4 can draw it, for example in Mermaid.
- **Degree distribution not drawn:** offered as optional item 10 and skipped by the team. It would need a Spark pass over `graph/`.
