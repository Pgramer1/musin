## 1. Purpose

PRD §16 counts the project as done only if the pipeline runs from a clean clone on the pinned snapshot. Until now every run happened in the one checkout that grew with the project, which hides missing steps, files that exist only locally, and README text that has drifted. F6.5 follows the root README literally, as a new team member would, in a fresh clone with a fresh data root, records every place where it was wrong, missing or unclear, and fixes the README.

## 2. What was built

- A clean-clone check: fresh `git clone` in WSL, its own `.env`, preflight, a cold `docker compose build`, `up -d`, envcheck, dump verification, the whole sample chain (credits → contributions → years → graph build → checks → export), pytest and ruff, then the sample Neo4j import and one F4.5 query in the clone's own Neo4j.
- Two reproducibility proofs beyond "it ran": a bit-for-bit fingerprint match against the team's own earlier sample build, and an identical-package comparison between the freshly built image and the team's image (§7).
- README fixes for the nine findings in §7.2. The harness itself is in the README as **Verify the build → 6. Re-run the clean-clone check**.
- `setup/preflight.sh`: an unedited `MUSIN_DATA` placeholder now gives a clear message instead of "must be an absolute path" for a path that is absolute.

## 3. How it works

**Isolation (why there is a harness at all).** The team's `musin` project was running: the Spark container and Neo4j holding the final `full` graph with every P4 property, which the F6.2 demo needs. A second checkout must not touch them, and `docker-compose.yml` makes that hard on purpose: it fixes the project name (`name: musin`), the image tags (`musin-spark:f1.1`, `musin-neo4j:f1.1`) and the Jupyter/Spark UI host ports (8888, 4040). So the clone got:

- `COMPOSE_PROJECT_NAME=musin-f65` in its `.env` (overrides `name:`), so containers, network and volumes are its own;
- a `docker-compose.override.yml` with its own image tags (`*:f65check`, so the cold build cannot move the team's tags) and `ports: !override` for 18888/14040; Neo4j's ports are already in `.env` (17474/17687);
- its own data root `~/f65-check/data`, outside `$MUSIN_DATA` and `/mnt/c`.

Nothing else differs from the README: every command was the README's, run from the clone's root.

**Data.** Re-downloading the 8.1 GB snapshot and re-extracting it was not needed to test the code path and would take hours. `cp -al` gives the scratch root hard links to `dumps/`, `raw/` and the four full artist-level tables (`clean/artists`, `clean/special_artists`, `clean/artist_genres`, `clean/artist_primary_genre`): zero extra disk (the WSL disk stayed at 52 GB used), and a stage rewriting its output replaces files rather than editing them, so the originals cannot change. This is the README's "copy from a teammate" route. `ingest.download --verify-only` then re-checked the GPG signature and both SHA-256 sums of the linked dumps, which proves the clone works on the pinned snapshot `20261007-002147`.

**Alternatives rejected.** Cloning from GitHub was the plan but is blocked in WSL (finding 1); the clone was made from the local checkout at the identical commit (`d334630` = `origin/main`), which has the same tracked files and none of the untracked ones. Stopping the team's containers to free the ports was rejected (it would disturb the loaded graph's container). Pointing the clone at the real `$MUSIN_DATA` was rejected because the sample chain would overwrite the team's `sample/f0.05/`.

**Fingerprint cross-check.** The team's dev sample in `$MUSIN_DATA/sample/f0.05/graph/_manifest.json` was built on 2026-10-11 (commit `bde801a`) with the provisional G1 settings, before D-039 removed classical artists. The `classical` variant (`variants.classical`: `include_classical: true`) is exactly that old configuration, so the clone built `graph.build --sample 0.05 --variant classical` and fingerprinted its four tables with `musin.common.provenance.fingerprint`: equal fingerprints mean identical tables, regardless of row order or file layout.

## 6. How to run

The exact commands are in the README, **Verify the build → 6. Re-run the clean-clone check** (clone, hard-linked data root, project name, override), followed by Getting started step 3, step 4 with `--verify-only`, and the **Sample mode only** block from `clean.credits --sample 0.05` on. In this run, from the clone's root:

```bash
bash setup/preflight.sh
docker compose build && docker compose up -d
docker compose exec spark python -m musin.envcheck --config config/pipeline.yaml
docker compose exec spark python -m musin.ingest.download --config config/pipeline.yaml --verify-only
docker compose stop neo4j
docker compose exec spark python -m musin.clean.credits --config config/pipeline.yaml --sample 0.05
docker compose exec spark python -m musin.clean.contributions --config config/pipeline.yaml --sample 0.05
docker compose exec spark python -m musin.clean.years --config config/pipeline.yaml --sample 0.05
docker compose exec spark python -m musin.graph.build --config config/pipeline.yaml --sample 0.05
docker compose exec spark python -m musin.graph.checks --config config/pipeline.yaml --sample 0.05
docker compose exec spark python -m musin.export.neo4j_csv --config config/pipeline.yaml --sample 0.05
docker compose exec spark pytest -q
docker compose exec spark ruff check src tests
docker compose exec spark python -m musin.graph.sample --config config/pipeline.yaml --sample 0.05
bash neo4j/import_graph.sh sample-f0.05 --overwrite
docker compose exec spark python -m musin.analytics.separation --config config/pipeline.yaml --pair "Tom Petty" "Snoop Dogg"
```

Runtime on the reference machine (16 cores, WSL 18 GB, sample memory settings, the team's idle Neo4j still holding 8.8 GiB): cold image build about 7 min, sample chain credits → export 160 s, the whole check about 30 min including the build retry. Full mode: not run (§8).

The post-G1 main sample (the one the README now quotes) has fingerprints nodes_artist `387481633391837894478`, artist_genre `-4584429292439062699165`, edges `598257284874031480146`, edges_by_decade `1422477375125647364127`, and rebuilding it with `graph.sample` gave +0.00 % on every count.

**Same image as the team's.** The cold-built `musin-spark` image and the team's `musin-spark:f1.1` have the same Java (`17.0.20.1`) and an identical `pip freeze` (115 packages), and the GraphFrames 0.12.3 jars are present. Both Neo4j images are 5.26.30 with the same GDS jar (SHA-256 `246e3fbb…d0a4b47c`, the pin in `docker/neo4j/Dockerfile`). Java comes from Debian's `openjdk-17-jre-headless` without a version pin, so a later rebuild can get a newer patch release (§8).

**Team environment untouched.** Throughout, `musin-spark-1` and `musin-neo4j-1` kept running on their own images and ports, and the `f65check` images were removed afterwards (`docker image rm`).

## 8. Known issues and limitations

- **Full mode from a clean clone was not run.** It needs a multi-hour run (raw ingest, full chain, F4.1's ~3 h betweenness, and re-importing Neo4j, which would replace the demo graph). The sample run exercises the same code paths, the image is identical to the one that made the full results, and F5.1 ran the full-scale recording chain 12 times (fraction 1.0 × 4 core counts × 3 repeats); still, criterion 1's "full mode on the reference machine" is shown by the original runs, not by this check.
- **Not re-tested here:** the 8.1 GB download (the official server drops the snapshot around 2026-10-21; `--verify-only` covered the copied dump), `ingest.extract`/`ingest.raw`, profiling, F2.1/F2.5 (the clone used the team's tables via hard links), P4 analytics apart from F4.5, P5 benchmarks, the GPU container, and F6.1's `musin.report`. The one-time Windows setup (`wsl --install`, `.wslconfig`, Docker Desktop integration) was not re-done on a fresh Windows install.
- **GitHub clone untested end to end:** the clone came from the local checkout at the same commit because WSL has no GitHub login. The new README instructions for signing in were not run.
- **Unpinned OS packages:** `apt-get install openjdk-17-jre-headless …` takes the current Debian bookworm version; it matched today, but a future rebuild may get a newer Java patch. Pinning it, or recording the image digest, is a possible follow-up.
- **Fixed host ports 8888/4040** (finding 7) need a PRD §8.5 change to become `.env` keys; proposed as a follow-up, not done.
- **The team's stored dev sample is pre-G1** (finding 8). It was left as it is, because refreshing it writes to the shared data root; `graph.sample --sample 0.05 --accept-changes` does it in about 95 s.
- The scratch folder `~/f65-check` (clone + hard-linked data root; about 0.8 GB of its own data, most of it the clone's Neo4j store) is still on the WSL disk; delete it by hand when it is no longer needed.
