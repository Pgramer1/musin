## 1. Purpose

RQ3 asks how cross-genre collaboration changed by decade, so every shared recording needs a year. MusicBrainz recordings have no date of their own; only releases do, often partially and sometimes wrongly. This feature derives each recording's **first release year** (FR-07): the earliest plausible year among all releases it appears on, or null when none is known. F3.1 uses it for `first_year`/`last_year` on edges and for `edges_by_decade`.

## 3. How it works

1. **Dated release events:** `release_country` ∪ `release_unknown_country`, keeping events with a year. A release can be issued in several countries on different dates.
2. **Plausibility bounds ([D-023](../decisions.md#d-023--plausible-release-years-1877snapshot-year)):** an event counts only if `1877 ≤ year ≤ 2026`.
   - The lower bound is the phonograph (1877): no sound recording can have been released earlier.
   - The upper bound is the snapshot year (`snapshot_date`): a later date is a scheduled release that hadn't happened at snapshot time.
   - On the full dump this ignores **1** event before 1877 (year 206, on a modern pop single) and **225** after 2026 (2027 alone: 181; the rest up to 3036).
   - Genuine early recordings are kept: Edison's "Mary Had a Little Lamb" (1878), "Speaking to Mr. Blaine" (1888), and 1890s cylinders.
3. **Per release:** the minimum counted year.
4. **Per recording:** `track → medium → release`, then the minimum over all its releases. A re-issue never makes a recording younger; its earliest release decides.
5. **Every recording gets a row** (left join from `recording`): `first_year` is null when the recording is on no release or on no release with a counted date. Explicit nulls make the downstream rule visible: RQ3 drops them, the graph keeps them (PRD §6.3).

*Rejected:*

- **Clamping** bad years to the bounds. That would invent a date.
- **Using release *groups*' first-release date.** MusicBrainz computes it from the same release events, so it adds nothing, and it would date a recording by an album it may not be on.
- **Using the release `status`.** Cancelled releases were never issued, but `release_status` is not in the raw layer (D-014). Only 452 releases are affected, so it is noted as a limitation instead of widening `raw/`.
- **A tighter lower bound such as 1900.** It would drop about 1,270 genuine early release events; RQ3 starts in 1960 anyway (`analysis.decades`).

**Worked example (tests).** Recording 100 is on release 2 (dates: 2010) and release 3 (dates: 206 and 2001). 206 is ignored, so the first year is **2001**. Recording 101 is only on a release dated 2027, so it gets null. A recording on an unknown medium also gets null.

## 8. Known issues and limitations

- **First *release*, not recording, year.** A 1950s recording first issued on a 1990s compilation counts as 1990s; a live recording released years later counts at its release. RQ3 measures when collaborations reached a release.
- **Wrong but plausible dates survive.** E.g. a release "Rio" dated 1884 (probably a typo for 198x). Bounds only catch impossible years.
- **Cancelled releases** (452, `status` 38) are counted, because `release_status` isn't in the raw layer.
- **7.4 % of recordings have no year** (3,006,912). They stay in the graph and are left out of RQ3's decade metrics only (`edges_by_decade` invariant, PRD §8.1).
- **Data is concentrated in recent decades:** the 2010s have 33× as many dated recordings as the 1960s, so early-decade RQ3 shares rest on much less data.
