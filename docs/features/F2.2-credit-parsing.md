## 1. Purpose

Every collaboration edge starts from a recording's artist credit. PRD §8.2 splits credited artists into **main** and **featured**: main × main and featured × featured become `CO_CREDITED`, and main → featured becomes `FEATURED`. RQ3's featuring share depends on this split. This feature turns each recording's `artist_credit_name` rows into `(recording_id, artist_id, position, role)`, applies the special-artist filter from F2.1, and is the first `clean/` stage with a sample mode.

## 2. What was built

| Piece | What it is |

| `drop_special` | Anti-join with the broadcast `clean/special_artists` (15 rows), *after* roles are set |

| `musin.common.layers.layer_path` | Sample-mode output location `$MUSIN_DATA/sample/f<fraction>/…` ([D-019](../decisions.md#d-019--sample-mode-output-layout)); reused by every later stage |
| 5 tests | 7 credit shapes, placeholder handling, repeat collapsing, output types, sample paths |

## 3. How it works

1. **Sample (optional):** `sample_by_hash(recording, "id", f)` keeps recordings by hashed ID (FR-12). Only the `artist_credit_name` rows of credits those recordings use are read.
2. **Roles on the complete credit.** `credit_roles` computes, for each slot, `max(join_phrase rlike pattern)` over the window `partitionBy(artist_credit).orderBy(position).rowsBetween(unboundedPreceding, -1)`, i.e. over all *earlier* join phrases. If any matched, the slot is featured. This is exactly PRD §8.2 ("comes after a join phrase matching"):

   | Credit (join phrases) | Roles |
   |---|---|
   | `A feat. B & C` | A main, **B featured, C featured** (both come after "feat.") |
   | `A & B Feat. C` | A, B main; C featured (pattern is case-insensitive) |
   | `A feat.` (phrase on the last slot) | A main; nobody follows |
   | `A with B x C vs. D` | all main (ambiguous phrases, a documented PRD limitation) |
   | `A (featuring B) Left C` | B, C featured; `Left` does not match `ft` (word boundary) |

3. **Then remove special artists** ([D-020](../decisions.md#d-020--credit-roles-decided-before-removing-special-artists)). `[unknown] ft. X` keeps X as *featured*. If the placeholder were removed first, X would be the first slot and become main, and later stages would invent `CO_CREDITED` edges with whoever else is on the credit. Keeping X featured with no main artist means the recording yields no edge for X, which is correct: X's real collaborator is unknown. Positions keep their MusicBrainz values (not renumbered), so a gap shows that a placeholder was removed.
4. **Collapse repeats.** If one credit lists the same artist twice (5,204 slots in the full data), the artist gets one row: the first position, and `main` if any of its slots is main.
5. **Join to recordings** (credit-level work on 6.1 M rows, then one join to 40 M recordings) and write `clean/credits`. Recordings whose credit contained *only* special artists get no rows.

*Rejected:* a Python UDF that parses each credit as a list. The window function does the same in the JVM (RULES §5). Also rejected: storing credits per `artist_credit` with a separate recording map. FR-05 specifies recording-level rows, and F3.1 needs them that way to count shared recordings.

**Sample-mode layout ([D-019](../decisions.md#d-019--sample-mode-output-layout)).** Recording-level outputs of a sample run go to `$MUSIN_DATA/sample/f<fraction>/<layer>/`, e.g. `sample/f0.05/clean/credits`, so a sample never overwrites full data and several fractions can coexist. Artist-level tables (`clean/artists`, `clean/special_artists`) are not sampled and are always read from the full `clean/`.

## 8. Known issues and limitations

- **Vocaloid voicebanks dominate featuring.** Six of the ten most-featured artists are singing-synthesizer characters (初音ミク etc., type `Character`), because Vocaloid producers credit them as "producer feat. voicebank". A follow-up measurement showed that this barely affects RQ3: Character artists carry 2.6 % of FEATURED weight and move the featuring share by at most 0.0007 per decade. The real risk is RQ1/RQ4, because 初音ミク is the largest hub in the graph (2,282 collaborators). Resolved by [D-021](../decisions.md#d-021--character-artists-left-out-of-the-graph-with-a-sensitivity-run): `clean/credits` keeps Character artists, and F3.1 leaves them out of the graph via `filters.exclude_artist_types`.
- **Ambiguous join phrases count as main** (`&`, `,`, `with`, `x`, `vs.`), as PRD §8.2 specifies, so some guest appearances are `CO_CREDITED` instead of `FEATURED`. F1.4 counted ` with ` 29,693 and ` x ` 13,771 times.
- **Voice-actor credits** (`(CV:` join phrases, F1.4) don't match the pattern, so character and voice actor are both main and become `CO_CREDITED`.
- **Sample shares are recording-based.** A 5 % sample keeps 5 % of recordings, but 33.5 % of credited artists (677,537 of 2,020,965), because artists are spread over many recordings. Artist-level statistics from a sample are biased upwards (as noted in F1.4).
- **No credit-size filter here.** Recordings with more than `max_credit_size` artists are kept in `clean/credits`; FR-10 is applied when building edges (F3.1).
