## 1. Purpose

"How many collaborations separate Frank Sinatra from Snoop Dogg?" FR-19 asks for the shortest path between two artists in the collaboration graph. It makes the abstract graph concrete for the report and the live demo (F6.2), and shows how small the collaboration world is. F4.5 answers it for any pair, explains each hop (who worked with whom, how, and on how many recordings), and gives the same answer on every run.

## 2. What was built

- **`python -m musin.analytics.separation --pair A B [--pair …]`.** It runs on whatever graph `loaded_graph.json` names, like F4.1/F4.2. Artists are given by MBID or exact name.
- **`neo4j/06_separation.cypher`:** artist lookup, all shortest paths, hop relations, names by id. The same statements serve as saved queries for the Neo4j Browser demo (F6.2) with the same parameters.
- **Config key** `analysis.separation_max_paths` (D-036).
- **Output:** `separation_paths.csv`, one row per `--pair` of the run, plus a readable log of every path.
- **9 unit tests:** name resolution (unique, MBID first, ambiguous refused with candidates, missing), canonical-path choice with parallel relationships, no path, hop formatting, that both path queries are restricted to the four collaboration types (no untyped `[*]`), and that the CLI needs a pair.

## 3. How it works

1. **Resolve each artist** (`separation.resolve`): match `mbid = key OR name = key`, using the unique `mbid` constraint and the `name` index from F3.5. An MBID match wins. Several name matches are an error that lists each candidate's MBID, type, recording count and primary genre. Zero matches is an error.
2. **Enumerate the shortest paths** (`separation.shortest_paths`):
   - `allShortestPaths((x)-[:CO_CREDITED|FEATURED|PRODUCED_FOR|PERFORMED_FOR*]-(y))`: unweighted, either direction, at most `analysis.separation_max_paths` relationship paths;
   - return each path's `artistId` sequence.
3. **Pick the canonical path** in Python: deduplicate the sequences (two artists linked by both `CO_CREDITED` and `FEATURED` give two relationship paths over the same artists), count the distinct ones, and take the smallest sequence.
4. **Explain each hop** (`separation.hop_relations`): every collaboration relationship between consecutive artists, with its type, its direction (`→` from the earlier to the later artist on the path) and its `weight` (shared recordings, D-028).
5. **Guard and write:** check that the loaded graph didn't change (`check_still_loaded`), then write `separation_paths.csv`.

**Design choices and alternatives** (D-036):

- **Typed relationships.** Found during exploration: `(x)-[*]-(y)` also follows `IN_GENRE` into `:Genre` nodes, which turned Frank Sinatra → Snoop Dogg into "Sinatra – pop – Snoop Dogg" (2 hops through a genre). Restricting to the four COLLAB types gives the real answer: Sinatra – Bono – Snoop Dogg, also 2 hops but through a person. A unit test guards this.
- **`allShortestPaths` with a canonical pick, instead of `shortestPath`.** `shortestPath` returns one of the tied paths, and Neo4j doesn't promise which one. The hop count is unique either way, but a path in the report should come out the same on every run. Enumerating all shortest paths was as fast as `shortestPath` on every tested pair (≤ 0.07 s).
- **A cap with a flag instead of no cap.** On the full graph, two hub-adjacent artists could have very many tied paths. The cap bounds memory and time, and `capped = true` tells the reader that the count and the pick cover only the enumerated paths.
- **Refuse ambiguous names** instead of picking the artist with the most recordings: a silent pick can answer a different question than the user asked.
- **Pairs on the command line, not in config:** the report's pairs aren't chosen yet (F6.1/F6.2). Every row records MBIDs, so a table in `reports/tables/` says exactly which artists it describes.
- **Rejected:** weighted paths (the PRD asks for hops), and GDS shortest-path procedures (they need a projection and give nothing more for a two-artist query).

## 6. How to run

```bash
docker compose exec spark python -m musin.analytics.separation --config config/pipeline.yaml \
  --pair "Frank Sinatra" "Snoop Dogg" --pair "Johnny Cash" "Armin van Buuren"
# ambiguous names: pass the MBID the error message lists
docker compose exec spark python -m musin.analytics.separation --config config/pipeline.yaml \
  --pair 38712b4c-0fd4-4c65-8c7a-45676fecc973 "Nightwish"
```

It runs on the graph loaded in Neo4j and is light enough to run next to anything. Runtime on the reference machine: under 1 s for 4 pairs on the sample (each query ≤ 0.07 s), and on the provisional full graph (each query ≤ 0.36 s). On the post-G1 full graph the `seconds` column records 0.01–0.04 s per pair.

**Behaviour checks:**

- **Deterministic:** a second run of the same four pairs gave an identical table apart from `seconds`.

- **Genre-node trap fixed:** the typed query gives Sinatra – Bono – Snoop Dogg, where the untyped exploration gave "Sinatra – pop – Snoop Dogg".

## 8. Known issues and limitations

- **Example pairs.** The full results above are illustrative pairs on the post-G1 graph. The report's pairs are chosen in F6.1/F6.2.
- **No classical artists in the main graph** (D-039). A pair with a classical artist (such as Yo‐Yo Ma) has no answer on `full`, and paths can no longer pass through orchestras or classical soloists, which may lengthen some paths between other artists. Such a pair needs the `classical` variant graph imported first (F4.7), and the result must say which graph it came from.
- **Hops say nothing about strength.** A path through a single shared recording counts the same as one through hundreds. `hop_relations` shows the weights so a reader can judge.
- **Contribution edges shorten paths.** A session musician (`PERFORMED_FOR`) or producer (`PRODUCED_FOR`) can link worlds that never shared a billing, as in the Manfred Eicher example. This is intended (COLLAB, PRD §5) but should be stated wherever a path is shown.
- **37.5 % of sample artists are outside the largest connected component** (F4.2), so "no path" is a common answer for obscure artists.
- **The canonical path is a convention** (smallest artist ids), not "the most meaningful" path. With `capped = true` it is the smallest among the enumerated paths only.
