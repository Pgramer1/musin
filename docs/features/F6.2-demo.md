## 1. Purpose

The presentation has one slide for the working model, shown as a short video. FR-25 asks for the demo to run as saved Neo4j Browser queries on the real graph. The demo has to show the result of each research question on the full graph within about a minute, with queries that answer instantly and can't fail in front of an audience.

## 2. What was built

| Piece | What it is |
|---|---|
| `neo4j/10_demo.cypher` | 8 named, read-only statements with their parameters in the header (`:param` lines), ready to drag into the Browser's Favorites |
| `python -m musin.demo_check` | Runs every demo statement with the header's parameters on the loaded graph; fails if one errors or returns no rows |
| `tests/test_demo_check.py` | 3 tests: parameter parsing; every statement parses and uses only declared parameters; no statement writes |
| Demo script (§6) | Order, talking points and timings for the slide-4 video |

## 3. How it works

1. **The same file format as every other Cypher file** (`// @name` statements ending in `;`, RULES §7), so `musin.common.cypher.load_queries` reads it and the check runs exactly the text the Browser runs.
2. **Parameters live in the file header** as Browser `:param` commands, one per line. The check parses them from there, so there is one source and the dry run uses the demo's own values.
3. **Read-only by construction.** No statement creates, merges, sets or deletes; a test enforces it, so the demo can't change the graph the report describes.
4. **Fast on the full graph.**
   - The overview counts each relationship type separately, so Neo4j answers from its count store. The first version summed weights over every relationship and took 11.5 s.
   - Artist lookups use the `artist_name` index (F3.5); names aren't unique, so each lookup takes the artist with the most recordings.
5. **Same answers as the report.**
   - The path statement picks F4.5's canonical shortest path (smallest artist-id sequence, D-036).
   - The community statement uses F4.2's size-rank ids.
   - The bridge and centrality lists read the written-back properties of F4.1–F4.3.

   The dry run gives Sinatra → Stevie Wonder → Snoop Dogg, and community 1 is 43.6 % hip hop, as `separation_paths.csv` and `communities_top.csv` say.

*Rejected:*
- **A Neo4j Browser guide (`:play <url>`):** it needs `browser.remote_content_hostname_allowlist` and a web server for the guide HTML.
- **Neo4j Bloom:** not part of Community Edition.
- **The Streamlit explorer (FR-26, Could):** not built. A 5-minute talk has room for one short video, and the Browser shows the graph view directly.

## 6. How to run

Dry run, any time Neo4j holds the full graph:

```bash
docker compose exec spark python -m musin.demo_check --config config/pipeline.yaml
```

Runtime on the reference machine: 5.8 s for all 8 statements.

**Live, or to record the slide-4 video** (about 60–75 s; record the screen of http://localhost:7474 at 1920×1080):

1. Before recording: start Neo4j, open the Browser, log in, drag `neo4j/10_demo.cypher` onto Favorites, and paste the five `:param` lines from its header. In the Browser's graph style, colour `:Artist` by `primaryGenre` and caption by `name`.
2. The shots:

| # | Statement | Seconds | Say |
|---|---|---:|---|
| 1 | `demo_overview` | 8 | "The full MusicBrainz export as a graph: about 1.1 million artists and four kinds of collaboration." |
| 2 | `demo_top_bridges` | 10 | "Our bridge score: artists whose collaborators span many genres *and* who sit between groups." |
| 3 | `demo_artist` + `demo_artist_genres` | 12 | "Ry Cooder: rock by tag, but his partners come from blues, jazz, country, latin and more: 11 genres." |
| 4 | `demo_ego` | 12 | Graph view: the colours show genres meeting in one network. |
| 5 | `demo_path` | 10 | "Frank Sinatra to Snoop Dogg in two hops, via Stevie Wonder." |
| 6 | `demo_centrality` | 10 | "Three centrality measures, three different top tens." |
| 7 | `demo_community` | 8 | "The largest community is hip hop and electronic: a scene, not a genre." |

Keep the numbers on screen as the Browser shows them; don't read them out from memory (RULES §9).

## 8. Known issues and limitations

- **The video is not recorded yet.** Claude Code can't log in to the Browser on the team's behalf; the team records it with §6.
- **The demo needs the full graph loaded.** A re-import (another graph or a variant) wipes the written-back properties; re-run P4 or re-import `full` with its write-backs first (P4 §9).
- **Putumayo, a record label, is #1 in `demo_top_bridges`.** Say so; the report explains it as a data artefact (P4 §7).
- **The weighted-degree top 10 shows audiobooks and a live archive** (spoken word, D-040, still open).
- **`demo_path` is unbounded** like F4.5 (D-036). Neo4j prints an informational notice; for the demo pair it answers in 0.02 s.
- **FR-26 (Streamlit, Could) not built.**
