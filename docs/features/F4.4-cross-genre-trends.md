## 1. Purpose

RQ3 asks whether cross-genre collaboration has changed over the decades. F4.4 measures two shares for each decade from the 1960s to the 2020s:

- **cross-genre share:** the share of collaboration weight between artists of different primary genres;
- **featuring share:** the share of billed collaborations that are "feat." credits rather than equal co-credits.

Each shared recording counts in the decade of its first release year. The output is a table and a line chart for the report.

## 2. What was built

- **`python -m musin.analytics.trends [--sample 0.05] [--variant <name>]`.** A **Spark** stage on the Parquet graph layer, unlike F4.1/F4.2. It reads `edges_by_decade` and `nodes_artist` of the main, sample, or variant graph (D-035), just as F3.3 does.
- **`decade_shares()`:** the per-decade aggregation in Spark. **`complete_decades()`** adds empty decades so the series has no gaps.
- **Outputs:** `trends_by_decade.csv` (one row per decade) and `trends_by_decade.png`.
- **3 unit tests** on hand-made graphs: shares, null shares, decade filter, per-type weights summing to the total, empty-decade completion.

## 3. How it works

1. Read `edges_by_decade` (one row per edge × decade, `weight` = shared recordings first released in that decade, PRD §8.1) and keep decades `analysis.decades.from`…`to`.
2. Join each endpoint's `primary_genre` from `nodes_artist` (two left joins on `src_id` and `dst_id`).
3. Aggregate per decade:
   - `total_weight` and the weight of each of the four edge types;
   - `labelled_weight`: both endpoints have a primary genre (PRD §5 genre attribution rule);
   - `cross_weight`: labelled, with different primary genres.
4. Compute three shares. A share is null when its denominator is 0.
   - `cross_genre_share` = `cross_weight / labelled_weight` (PRD §5 RQ3);
   - `featuring_share` = `featured_weight / (featured_weight + co_credited_weight)`, over **all** edges, labelled or not (PRD §5 RQ3);
   - `labelled_share` = `labelled_weight / total_weight`. This is not a PRD metric but the coverage behind the cross-genre share, reported so the trend can be read honestly (§8).
5. Collect the aggregate (≤ 7 rows), add empty decades, write the CSV, draw the chart, and log how much of `edges_by_decade`'s weight lies inside the decade range.

**Design choices and alternatives:**

- **Spark on Parquet, not Neo4j.** The per-decade split exists only in `edges_by_decade`; the Neo4j edges carry `firstYear`/`lastYear`, not a weight per decade. P3 built `edges_by_decade` for exactly this (§8.1), and F3.3 checks its invariant.
- **The weights are D-028 shared-recording counts**, so a recording counts once per artist pair across edge types, and the shares are shares of recordings, not of edge rows.
- **Weight-based shares, not edge counts**, as the PRD defines them. `edges` (row count) is in the table too, for reference.
- **`labelled_share` added to the table** (no new metric, no decision needed). Without it, a reader can't see that the cross-genre share is computed on a shrinking subset.
- **The chart** reuses the F1.4 figure style (`musin.profiling.figures`): light surface, blue then orange, 2 px lines, direct end labels, a legend, and one percentage axis for both series (both are shares, so there is no dual axis). The two-colour palette was checked with the dataviz validator against the chart surface `#fcfcfb`: lightness, chroma, colour-blind separation (ΔE 24.7), normal-vision separation (ΔE 33.6) and contrast all pass.
- **Rejected:** weighting by distinct artist pairs instead of recordings (not the PRD definition), and per-period primary genres (the data has one genre profile per artist; see §8).

## 5. Configuration

| Key (`config/pipeline.yaml`) | Value used | Meaning |
|---|---|---|
| `analysis.decades.from` | 1960 | first decade (its start year) |
| `analysis.decades.to` | 2020 | last decade, inclusive (the 2020s) |

The stage checks that both values are decade starts and that `from ≤ to`, and fails otherwise.

## 6. How to run

```bash
docker compose exec spark python -m musin.analytics.trends --config config/pipeline.yaml --sample 0.05   # sample
docker compose exec spark python -m musin.analytics.trends --config config/pipeline.yaml                # full (after G1)
```

It reads only Parquet, so it doesn't matter which graph Neo4j holds, but it shouldn't run while Neo4j does heavy work (PRD §7.2). Runtime on the reference machine: sample **9 s**, full **13 s** (Spark, Neo4j idle; 2026-10-19).

What the final full graph shows:

- **Featuring rises sharply from the 1990s.** It was 3–4 % before 1990, 11 % in the 1990s, 19 % in the 2000s and 23 % in the 2010s, then 19 % in the 2020s. This fits the spread of "feat." credits with hip hop and pop. The 2020s dip covers an incomplete decade, so it is not yet a trend.
- **The cross-genre share mostly rises.** It goes from 16 % in the 1960s to 24–25 % in the 1970s–80s, dips to 21 % in the 1990s, then climbs every decade to 28 % in the 2020s, the highest of all seven.
- **Coverage falls at the same time** (labelled share 61 % → 29 %), because newer artists are tagged less often. The cross-genre trend therefore rests on a shrinking, possibly more popular subset (§8).
- **Classical changed the shape** (see the comparison above). The report should say that the RQ3 answer depends on the OD1 choice.

## 8. Known issues and limitations

- **Spoken word is still in the graph.** G1 left the spoken-word filter (g1-scope-gate.md §2.1) open, so audiobook author–narrator pairs still count, mostly as CO_CREDITED weight in recent decades. The classical decision (D-039) is applied.
- **Primary genre is fixed per artist, not per period** (PRD §5 RQ3). An artist who moved from folk to rock counts as one genre in every decade.
- **Falling label coverage.** The cross-genre share is computed over labelled edges only, and their share of all weight halves between the 1960s and the 2020s. If tagged recent artists are more mainstream than untagged ones, the recent cross-genre share is biased towards them. The table reports `labelled_share` so the report can say so.
- **First-release year is a proxy for when the collaboration happened**, and recordings without a known year are left out (F2.4).
- **Small early-decade FEATURED counts.** 1,622–5,355 FEATURED recordings per decade before 1990 on the full graph: enough for a share, but small next to the hundreds of thousands later.
- **Contribution credits are sparse and era-dependent** (F1.4: producer credits peak in the 1960s–80s). They count in the cross-genre share's weight but not in the featuring share.
