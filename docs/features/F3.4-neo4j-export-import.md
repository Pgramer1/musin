## 1. Purpose

P4 runs on Neo4j + GDS (PRD §5.5), so the Parquet graph layer has to get into Neo4j:

- **exactly:** same counts, same values, integer ids and weights
- **quickly enough** to switch between the sample and full graph, since Community Edition holds one graph
- **traceably:** every P4 number must say which graph it came from

F1.5 proved the `neo4j-admin database import full` mechanics on a 12-artist toy graph. F3.4 produces the §8.3 CSVs from the real graph, imports them, and verifies the result in Neo4j against the Parquet source.

## 2. What was built

| Piece | What it is |
|---|---|

| 18 tests | Header types, headers against the PRD §8.3 text, a real CSV round trip of hazardous values, null encoding, the edge frame, the newline guard, the verifier's expected-missing and comparison logic |

## 3. How it works

### 3.1 Export

1. **Gate.** The graph's current content fingerprints (F3.2) must equal those in its last passing `_checks.json` (F3.3). An unchecked or changed graph is never exported.
2. **Frames.** Each file maps 1:1 to a §8.3 header (D-016 `{id-type:long}`).
   - `artists`: `nodes_artist` with `artist_type` → `type`. `genre_votes` is not part of the Neo4j model (§8.3) and is not exported.
   - `genres`: the 15 parent genres of the mapping (D-024), including any without artists.
   - `in_genre`: `artist_genre`.
   - One `edges_<type>` file per edge type.
3. **CSV dialect** ([D-031](../decisions.md#d-031--neo4j-export-layout-csv-dialect-and-the-loaded-graph-marker)). Every Spark option is explicit, because three defaults are wrong for `neo4j-admin`:
   - The escape character is a backslash. Names contain `"` (2,133 graph artists) and `\` (30), so the escape is set to `"` (RFC 4180 doubling).
   - The writer trims leading and trailing whitespace. Trimming is switched off.
   - Empty strings are written as `""`. They are mapped to null, which becomes an empty unquoted field and therefore a missing property. The graph has no empty strings and no line breaks (both measured on 2026-10-11), but a line break stops the export instead of silently needing `--multiline-fields`.
4. **Read-back.** Each file is parsed again with exactly the types its header declares (`FAILFAST`). Its content fingerprint must equal the source frame's. During development this caught `""` coming back as null, the reason for the empty-string rule.
5. **Layout.** Each file is `<file>.header.csv` plus `<file>/part-*.csv`, at most 1 M rows per part (the PRD §8.3 "split into parts with a separate header file"). The part files are listed explicitly in `_import_args.txt`, so the import depends on neither the importer's regex support nor a hand-kept file list. `_export.json` records the source fingerprints, rows, parts, and null counts per header field.
6. **Location.** Sample exports also go under `import/` (`import/sample-f0.05/`), not the D-019 sample tree, because docker-compose mounts only `$MUSIN_DATA/import` into Neo4j (D-031 §1).

### 3.2 Import

`neo4j/import_graph.sh` follows the F1.5 script, with three differences:

- It deletes `loaded_graph.json` **first**, so a failed import never leaves a stale claim about the database content.
- It runs strict: `--bad-tolerance=0`, `--skip-bad-relationships=false`, `--skip-duplicate-nodes=false`, with a per-graph report file.
- It reads the file arguments from `_import_args.txt`.

As in F1.5, the database name comes before the greedy `--nodes`/`--relationships` options, and the importer runs in a one-off container of the Neo4j image while the server is stopped.

### 3.3 Verification (39 checks)

| Group | Checks |
|---|---|
| Importer | the report file is empty (0 bad rows) |
| Shape | labels are exactly `Artist`, `Genre`; node count per label and relationship count per type equal the exported rows |
| Types (D-016) | `artistId`, `recordingCount`, `beginYear` are `INTEGER`; per edge type `weight`, `firstYear`, `lastYear` are `INTEGER`; `share` is `FLOAT`; `artistId` is distinct |
| Nulls | for every optional property (`type`, `areaName`, `beginYear`, `primaryGenre`, and per edge type `firstYear`/`lastYear`) the number of nodes or relationships **without** it equals the exported nulls; `mbid` and `name` are never missing |
| Schema | no Artist property outside the §8.3 list; Genre nodes have only `name` |
| Values | property-by-property comparison with Parquet for every artist whose name contains `"`, `,` or `\` (up to 200 each) plus 500 hashed artists, and for all out-edges of 300 hashed artists (no edge missing, none extra) |

No index exists yet; F3.5 creates the constraints. The lookups therefore use one label scan with `IN $ids` instead of per-id seeks. On the full graph, both spot checks together took 11 s, including the Spark reads that pick the sample.

*Rejected alternatives:*
- **`LOAD CSV`:** RULES §7, too slow.
- **A Neo4j node that records the graph version:** it would add a label to the §8.3 model, a contract change. The marker file plus fingerprints does the same job.
- **One CSV per table via `coalesce(1)`:** it doesn't scale and ignores §8.3's split-file format.
- **Regex file patterns in the import command:** explicit lists are unambiguous.

## 6. How to run

```bash
# sample graph (the dev sample graph, M2)
docker compose exec spark python -m musin.export.neo4j_csv --config config/pipeline.yaml --sample 0.05
bash neo4j/import_graph.sh sample-f0.05 --overwrite
# full graph (M3); stop Neo4j first if it is busy: the export is a Spark job
docker compose exec spark python -m musin.export.neo4j_csv --config config/pipeline.yaml
bash neo4j/import_graph.sh full --overwrite
cat $MUSIN_DATA/neo4j/loaded_graph.json        # which graph Neo4j holds
```

Runtime on the reference machine:

| Step | Sample | Full |
|---|---:|---:|
| Export | 17 s | 30 s |
| `neo4j-admin` import | 2.6 s / 3.3 s | 6.9 s |
| Verification | 29 s | 41 s |
| Whole script | 37 s / 46 s | 54 s |

The sample was imported twice (before and after the full graph). Server start-up takes most of the verification time.

## 7. Verification and results

Runs 2026-10-11, snapshot `20261007-002147`, graph from F3.1 at commit `2ac5547` (F3.3 checks passing).

**Full graph:** all **39 checks passed**.

- **Importer:** 1,180,954 nodes (1,180,939 Artist + 15 Genre) and 3,983,763 relationships (3,541,659 edges + 442,104 IN_GENRE) in 6.9 s, with an empty report.
- **Counts per type:** CO_CREDITED 1,731,537 · FEATURED 734,524 · PRODUCED_FOR 291,319 · PERFORMED_FOR 784,279 · IN_GENRE 442,104. Each equals the exported rows and the F3.3-checked Parquet counts.
- **Missing properties match exported nulls exactly:**
  - Artists: `type` 263,182, `areaName` 590,998, `beginYear` 936,606, `primaryGenre` 904,601.
  - Edges without years: CO_CREDITED 52,652, FEATURED 10,747, PRODUCED_FOR 3,143, PERFORMED_FOR 15,025 (sum 81,567, the F3.1 count of undated edges).
- **Spot checks:** 929 artists, including every hazardous-name class, and 1,634 edges are identical to Parquet, with no extra edges.

**Sample graph:** all 39 checks passed, in both imports: 310,253 artists, 15 genres, 734,143 relationships, 905 artists and 680 edges spot-checked.

**Neo4j now holds `sample-f0.05`** (`loaded_graph.json`, edges fingerprint `-728045217745244929017`), as agreed for M2. The full graph was imported, verified, and then replaced.

**Tests:** `pytest` 144 passed (126 earlier + 18 new); `ruff check` / `ruff format --check` passed; `bash -n` passes on both shell scripts.

Tests and development runs caught three defects before the full run:
- the newline guard failed on a frame with a single string column
- `""` round-tripped to null (now normalised to null on purpose)
- the edited F1.5 script had CRLF line endings in the Windows working copy, which broke bash in WSL (converted to LF; `.gitattributes` stores LF anyway)

## 8. Known issues and limitations

- **One graph at a time** (Community Edition). Switching takes about 1 min. `loaded_graph.json` is the only record of which graph is loaded, and anyone importing outside these two scripts bypasses it.
- **No constraints or indexes yet:** F3.5 adds them. Until then, lookups by `artistId` scan the label.
- **The smoke-test change was not re-run** (it would replace the sample graph). The script passes `bash -n`, and the change is two lines.
- **Spot checks are samples:** about 900 artists and 700–1,600 edges are compared value by value. Every row's count, type, and null status is checked in aggregate.
- **Empty strings become missing properties**, which is fine for this graph (it has none), but a deliberate rule.
