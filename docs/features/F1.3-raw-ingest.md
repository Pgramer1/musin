## 1. Purpose

The dump files are headerless PostgreSQL `COPY` text: no column names, no types, backslash escapes, `\N` for null. Every later stage needs the same tables as typed, columnar data it can trust. This feature defines an explicit schema for every table we use, extracts those tables from the verified archives, and converts them, without filtering, into the `raw/` Parquet layer. If anything doesn't match, it fails instead of guessing.

## 3. How it works

### 3.1 Which tables

The 21 tables of PRD §6.2, plus **`l_artist_release`**, because F1.4 must compare release-level and recording-level credit coverage to decide OD7 (D-014). Everything else is left out: aliases, `recording_tag`, link attributes, the 16 GB edit history. Listing the archives (79 s for the core dump with `lbzip2`) showed `tag`, `artist_tag`, and `release_group_tag` in `mbdump-derived.tar.bz2` and the other 19 in `mbdump.tar.bz2`. `genre` and `genre_alias` are in the core dump.

### 3.2 Where the column order comes from

Both archives contain `SCHEMA_SEQUENCE` = **31** (and the same `TIMESTAMP` 2026-10-07 00:21:48 UTC and `REPLICATION_SEQUENCE` 189552, so they are one consistent snapshot). The `musicbrainz-server` `production` branch at dump time was commit `c93f815c` (tag `v-2026-09-21.0`), whose `lib/DBDefs/Default.pm` declares `DB_SCHEMA_SEQUENCE { 31 }`. Its `admin/sql/CreateTables.sql` (SHA-256 `92d1981a…ecb13`) is the column source.

**Generated, not hand-typed, schemas.** Typing 199 columns by hand invites a silent off-by-one that would shift every value. `generate.py` extracts each `CREATE TABLE` block, keeps lines of the form `<lowercase name> <type>`, maps the type through a fixed table, and **fails on any type it doesn't know**. RULES §5 still holds: the schemas are explicit and committed in `tables.py`, and nothing parses SQL at run time. Two parser bugs were caught during development: the DDL writes `uuid` in lowercase in some tables (`area.gid` and `artist_type.gid` were initially dropped), and multi-line `CHECK` constraints produce lines like `end_date_year IS NULL`, which are skipped explicitly. The tests now cover both.

| Postgres | Spark (raw) | Note |
|---|---|---|
| `SERIAL`, `INTEGER` | int | widened to long for `artist_id` etc. in `clean/` (PRD §8.1) |
| `SMALLINT` | short | e.g. `begin_date_year`, `position` |
| `TEXT`, `VARCHAR(n)`, `UUID` | string | UUIDs kept as text (`gid` → `mbid` later) |
| `BOOLEAN` | boolean | dump writes `t` / `f` |
| `TIMESTAMP WITH TIME ZONE` | timestamp | Postgres `…+00` offsets parse natively; session time zone UTC |

### 3.3 Extraction

`tar -I lbzip2 -xf <archive> -C extracted/<archive-stem>/ SCHEMA_SEQUENCE TIMESTAMP REPLICATION_SEQUENCE mbdump/<table> …`. Each archive gets its own folder because both use the `mbdump/` prefix. After extraction the stage reads `SCHEMA_SEQUENCE` and stops if it isn't the one the schemas were generated for. *Rejected:* streaming the `.tar.bz2` straight into Spark. Spark cannot split a bz2 *tar* stream, so it would be single-threaded, and every re-run would decompress the archive again.

### 3.4 Parsing COPY text without UDFs

In COPY text format a real TAB or newline inside a value is always escaped, so:

1. `spark.read.text` with `lineSep="\n"` gives one row per line.
2. `split(value, "\t", -1)` gives the fields exactly; `-1` keeps trailing empty fields.
3. **Field count:** the first column is wrapped in `when(size(fields) == n, …).otherwise(raise_error(…))`, so a wrong-width line fails the job with the table name and the first 200 characters of the line. The check sits inside a column that is always selected, so Spark cannot optimise it away.
4. **Null:** a field equal to `\N` becomes null. An escaped literal `\N` in a name arrives as `\\N` and stays text.
5. **Unescape** (string columns, only when the value contains a backslash): `\\` → NUL placeholder, then `\n \t \r \b \f \v` → control characters, then placeholder → `\`. The placeholder step means an escaped backslash followed by `n` (`C:\\new`) stays `C:\new` instead of becoming a newline. NUL is safe because Postgres text cannot contain it. Uses `F.replace` (Spark 3.5), not regex.
6. **Casts** run with `spark.sql.ansi.enabled=true`, so a malformed number, an overflow (e.g. 40000 into a short), or an impossible timestamp **raises** instead of silently becoming null (checked in a probe and in the tests). Booleans other than `t`/`f` raise explicitly.

*Rejected:* Spark's CSV reader with `quote` disabled. It doesn't decode backslash escapes, so text values would keep `\n` and `\\` literally. A Python UDF would be correct but slow on 58 M track rows (RULES §5).

### 3.5 Writing `raw/`

Per table: count input lines, parse, `write.mode("overwrite").parquet(raw/<table>)`, re-read the Parquet count, and fail if the two differ. Snappy Parquet, partitioned only by Spark's input splits; order is irrelevant in a faithful copy. `raw/_manifest.json` records the snapshot, schema sequence, source commit, and each table's rows, column count, TSV bytes, Parquet bytes, and seconds. `--tables` restricts a development run; the full run rewrites every table.

## 5. Configuration

No new config keys. Used: `snapshot_date` (`20261007-002147`), `paths.dumps`, `paths.raw`, `source.files`. Pinned in code, because they define the parser rather than an analysis choice: `SCHEMA_SEQUENCE = 31` and `SOURCE_COMMIT` in the generated `tables.py`, and the table list in `generate.py` (D-014). `.env`: `SPARK_DRIVER_MEMORY=12g`.

## 6. How to run

```bash
# extract the 22 tables (all, or a subset for development)
docker compose exec spark python -m musin.ingest.extract --config config/pipeline.yaml [--tables tag,artist_tag]
# ingest to raw/ Parquet (all, or a subset)
docker compose exec spark python -m musin.ingest.raw --config config/pipeline.yaml [--tables tag,artist_tag]
# only when a new snapshot has a different SCHEMA_SEQUENCE:
python -m musin.schemas.generate --sql CreateTables.sql --commit <sha> --schema-sequence <n>
```

There is no `--sample` here: `raw/` is a faithful copy, and sampling by hashed recording ID starts at the graph layer (F3.2, FR-12). `--tables` serves as the small development mode. Runtime on the reference machine: extraction **136 s** (core 126 s, derived 10 s), ingest **157 s** (wall time 169 s including JVM start); development run with 12 small tables: 85 s + 14 s.

## 8. Known issues and limitations

- **Extracted text is kept** (17.6 GB) so `raw/` can be rebuilt without decompressing again. It can be deleted (`extracted/`) and re-created in 136 s if disk gets tight.
- **Downvoted tags:** 30,801 of 770,225 `artist_tag` rows have `count ≤ 0`. `raw/` keeps them as they are; F2.5 must decide how to treat them.
- **New snapshots:** if a future snapshot has another `SCHEMA_SEQUENCE`, extraction stops; regenerate `tables.py` from the matching `CreateTables.sql` and record a decision.
- **Raw types are Postgres-faithful,** not contract types: IDs are 32-bit ints and years are shorts. `clean/` must widen them to the PRD §8.1 types.
- **ANSI mode is set only for this stage** (`spark.conf.set` in `raw.py`), not globally in `get_spark()`. Later stages keep Spark's default casting unless they opt in.
- **`wsl.exe` re-parses commands.** Running multi-step commands as `wsl.exe -- bash -c '…'` expands `$variables` in the wrong shell (during development this made `tar` print a whole archive to the terminal). Run multi-step shell work from a script file.
